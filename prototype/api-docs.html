灵镜 开放 API

让你的 AI Agent 通过 HTTP 直接调用灵镜的生图、生视频、生音乐、语音能力。密钥即成员本人身份,消耗本机构积分。

1. 认证

在系统设置 → API 密钥创建密钥(格式 lj_sk_…,明文仅创建时显示一次)。每个请求带上:

Authorization: Bearer lj_sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

密钥以创建者身份行动:权限、计费、作品归属都和这个人网页操作一致。当前成员角色只有管理员 / 创作者两种,两者都可发起生成。密钥只能访问生成相关接口,不能管理账号 / 成员 / 支付(其余接口返回 403 SCOPE_FORBIDDEN)。

主人被停用或密钥被吊销后,密钥立即失效(返回 401 UNAUTHORIZED)。管理员可在系统设置吊销任意密钥。

2. 提交生成

POST/api/jobs

所有生成走同一个提交接口,用 type 区分工具。返回任务 id,再轮询取结果(见 §3)。

type工具关键参数
ai_imageAI 图片(文生图 / 图生图)prompt, count, model?, mode?, imageRefs?
video_t2v文字转影片prompt, model?, resolution?, duration?
video_i2v图片转影片(首帧 / 首尾帧 / 参考)task, imageRefs, prompt?
video_r2v多模态参考生影片prompt, imageRefs?, videoRefs?, audioRefs?
video_edit影片编辑videoRef, prompt
tts文字转语音text, voiceRef
ai_musicAI 音乐prompt

model 缺省用当前默认模型;可选项见 §5 的模型列表接口。voiceRef / avatarRef 等 ID 见 §6 发现接口。

curl -X POST https://你的域名/api/jobs \
  -H "Authorization: Bearer lj_sk_..." \
  -H "Content-Type: application/json" \
  -d '{"type":"ai_image","prompt":"一只在雪地里的柴犬","count":1}'

# → 202 {"id":"...","status":"queued","cost":11}

幂等(强烈建议)

Agent 超时重试是常态。带上 Idempotency-Key 请求头(客户端生成的任意唯一串),同一个键的重复提交不会重复扣费:

-H "Idempotency-Key: 8f14e45f-你的唯一串"
  • 同键 + 相同请求体 → 返回原任务(200,不再扣费)
  • 同键 + 不同请求体 → 409 IDEMPOTENCY_CONFLICT
  • 幂等作用域按机构隔离,不同机构互不影响

3. 查询任务 / 取结果

GET/api/jobs/:id — 返回状态。终态 done 后含产物;failed 时 error 为中文可读原因(如送审拒绝、余额不足)。

GET/api/jobs — 列最近任务(仅本人创建的)。会话中断、job_id 丢失时用它找回。MCP 侧对应 list_jobs(§10)。

GET/api/jobs/:id/download/:idx — 下载第 idx 个产物(签名 URL 重定向)。

视频类任务是分钟级异步。建议轮询 GET /api/jobs/:id 的间隔 ≥ 5 秒,直到 status 为 done 或 failed。读接口限速较宽(见 §7)。

响应含 channel 字段标记任务来源:rest(本接口提交)/ mcp(MCP 工具提交)/ web(成员在网页上创建)。经密钥提交的任务会在网页端的生成记录里显示「API 创建」/「MCP 创建」徽章,便于机构区分人工创作与 Agent 产出。该字段由服务端按认证方式判定,请求体无法指定。

4. 费用预估

POST/api/jobs/estimate — 参数同提交,返回 {cost}。生成前预估扣费,成功后按真实用量结算。

本端点的校验比真提交宽松(为网页端「边填参数边实时报价」而设):时长超模型范围会被截断后照样给价、分辨率不合法照样计价、voiceRef 不校验存在性。因此「estimate 通过」不保证「同参数提交也通过」。Agent 请改用 MCP 的 dry_run: true(§10)—— 它走的是与提交完全相同的校验路径。

5. 模型列表

GET /api/image-models · /api/video-models · /api/i2v-models · /api/r2v-models · /api/edit-models · /api/tts-models

让 Agent 自己发现可用模型、能力、分辨率档与计价。

6. 发现音色 / 形象 · 上传参考素材

GET/api/voices · GET/api/avatars — 拿到 voiceRef / avatarRef ID(TTS、数字人视频需要)。

POST/api/image-uploads · /api/video-uploads · /api/audio-uploads — 上传参考素材(multipart/form-data),返回存储 key 供 imageRefs 等引用。

⚠️ 合规:上传含真人的素材(图片 / 视频 / 音频)必须持有被摄主体或本人的授权(consent=true),这与网页端同一口径。责任主体为你的机构。深度合成生成受平台内容审核约束。
v0.9.2 起参考音频也要求 consent:声纹属个人信息,且参考音频可直接驱动影片生成。

7. 限速

按密钥计数,读写分级。超限返回 429 RATE_LIMITED,请指数退避后重试。

口径上限包含
写60 次 / 分钟 / 密钥提交生成、上传
读300 次 / 分钟 / 密钥查询任务、模型列表、余额
MCP 按「条」计,不按「次请求」计。JSON-RPC 允许一次请求装多条消息(数组),服务端逐条分档、逐条计数 —— 一个装了 10 条 generate_* 的数组消耗 10 次写额度,不是 1 次。单次请求最多 20 条消息,超出返回 413 PAYLOAD_TOO_LARGE。

8. 余额

GET/api/credits/balance — 返回 {balance}(当前机构积分)。余额不足时提交返回 402 INSUFFICIENT_CREDITS。

9. 错误码

开放接口的错误响应统一为 {"error":"中文可读","code":"机器可读"}。按 code 决定是否重试:

codeHTTP含义适用可重试?
UNAUTHORIZED401密钥无效 / 已吊销 / 主人被停用REST · MCP否
SCOPE_FORBIDDEN403密钥访问了生成面以外的接口。路径写错(不存在)也返回本码 —— 响应的 allowed 字段列出全部可用端点,先照它核对路径,再考虑权限REST否
ROLE_FORBIDDEN403该角色的密钥不能发起生成。当前角色只有管理员 / 创作者两种,两者都可生成 —— 这是为将来的只读角色预留的防御性拦截,正常不会遇到REST · MCP否
RATE_LIMITED429超出限速,或 MCP 上传通道并发数据量已达上限(带 Retry-After)REST · MCP是(退避)
INSUFFICIENT_CREDITS402积分余额不足REST · MCP否(充值后)
IDEMPOTENCY_CONFLICT409相同幂等键但请求体不同REST · MCP否
INVALID_PARAMS400参数错误(缺必填、取值不在该模型允许范围、组合非法…)。错误文案是中文可读的具体原因,照它改参数即可MCP否
INVALID_INPUT_FILE400上传的文件格式不支持、超大小上限、或 base64 解不出字节MCP否
NOT_FOUND404任务不存在或无权访问(跨成员查任务也返回本码)MCP否
PAYLOAD_TOO_LARGE413两种触发:①请求体超过 /mcp 上限 —— 图片可减张数或压缩,视频/音频请改用 REST 上传端点;②单次 JSON-RPC 批量超过 20 条消息 —— 拆分后重发。看 error 文案区分MCP否
UPLOAD_FAILED500对象存储写入失败(服务端侧问题)MCP是(退避)
(无 code)400参数错误(REST 侧,文案为中文可读原因)REST否

内容审核拒绝不在提交时返回,而是任务落为 failed,error 字段说明原因(轮询 §3 可见)。

10. MCP(Claude Code / Cursor 原生接入)

用同一把 lj_sk_ 密钥,在 Agent 里加一段配置即可原生调用。端点:POST/mcp(Streamable HTTP,无状态)。

{
  "mcpServers": {
    "lingjing": {
      "type": "http",
      "url": "https://你的域名/mcp",
      "headers": { "Authorization": "Bearer lj_sk_..." }
    }
  }
}

连上后 Agent 会自动读到一份使用说明(MCP instructions)与全部工具的参数 schema —— 它据此决定调哪个工具、怎么填参数,你不需要额外提示。工具集(生成类全异步:返回 job_id,用 get_job 轮询):

工具说明REST 对应
upload_image上传参考图(base64,≤10MB × ≤9 张),返回 imageRefs/api/image-uploads
upload_video上传视频(base64,≤20MB、2–60 秒),返回 videoRef/api/video-uploads
upload_audio上传参考音频(base64,≤20MB,需 consent),返回 audioRef/api/audio-uploads
generate_image文生图 / 图生图ai_image
generate_video文字转影片video_t2v
generate_video_from_image图片转影片(task:首帧 / 首尾帧 / 参考生成)video_i2v
generate_video_from_refs多模态参考生成影片(图 + 视频 + 音频任意组合)video_r2v
edit_video影片编辑(换装 / 风格化 / 局部替换)video_edit
generate_musicAI 音乐(mode:song 有人声 / instrumental 纯音乐)ai_music
generate_speech文字转语音(需 voice_ref;支持情绪 / 语速 / 音高 / 语言)tts
get_job查任务状态;完成后含签名下载 URLGET /api/jobs/:id
list_jobs列最近任务(会话重启后找回 job_id)GET /api/jobs
get_balance查本机构积分余额/api/credits/balance
list_models按 kind(image/video/i2v/r2v/edit)列模型及其能力边界/api/*-models
list_voices / list_avatars发现可用音色 / 数字人形象(只读)/api/voices · /api/avatars

先问价再花钱:dry_run

每个 generate_* 都接受 dry_run: true —— 只返回预估费用与当前余额,不提交、不扣积分。它走的是与真提交完全相同的校验,所以「dry_run 通过」就意味着「同参数提交也会通过」。想真做时,把同一份参数去掉 dry_run 再发一次即可。

generate_video_from_refs({ prompt: "…", imageRefs: [...], dry_run: true })
  → { cost: 240, balance: 8600 }
generate_video_from_refs({ prompt: "…", imageRefs: [...] })
  → { job_id: "…", status: "queued", cost: 240 }
旧的 estimate 工具已标记废弃(仍可用,将在后续版本移除)。它的参数是扁平化的,覆盖不了图转影片 / 参考生成 / 影片编辑的完整字段,请改用 dry_run。

超时重试不双扣:idempotency_key

每个 generate_* 都接受可选的 idempotency_key。网络超时后重试同一次请求请传相同的值 → 返回原任务、不重复扣费;想再生成一份(哪怕参数完全一样)请换一个新值。语义与 REST 的 Idempotency-Key 请求头一致(§2)。

三条闭环

  • 图生图:upload_image → generate_image(mode="img2img" + imageRefs)→ get_job
  • 图转影片:upload_image → generate_video_from_image(task="first_frame" + imageRefs)→ get_job
  • 参考生成 / 影片编辑:upload_image / upload_video / upload_audio → generate_video_from_refs 或 edit_video → get_job

大文件走 REST

MCP 是 JSON-RPC,文件只能 base64 内联,单个素材上限约 20MB(受 /mcp 请求体上限约束,base64 比原始字节大约 33%)。手机实拍视频经常超限 —— 这时改用 REST 上传端点即可,同一把 lj_sk_ 密钥,该端点一直在密钥作用域内,不需要额外权限:

curl -X POST https://你的域名/api/video-uploads \
  -H "Authorization: Bearer lj_sk_..." \
  -F consent=true -F video=@clip.mp4
# → {"videoRef":"video-inputs/…","duration":42.5,...}

拿到 videoRef 后照常填进 edit_video / generate_video_from_refs。

MCP 侧做不到的事

以下能力只能在灵镜后台网页端完成,MCP 不提供对应工具(Agent 会在 instructions 里读到这一点,不会反复尝试):

  • 数字人口播视频(形象 + 文案 → 对口型视频)
  • 创建数字人形象(需上传素材并完成授权存证)
  • 声音克隆 / 设计音色(需授权存证)
「参考图」不是「数字人形象」:参考图用于图生图 / 图转影片,upload_image 即可;数字人形象只用于口播视频,需在后台创建并完成授权存证,API 侧只读(list_avatars / GET /api/avatars)。
⚠️ 合规:含真人的图片 / 视频必须持有被摄主体授权,上传时传 consent=true,责任主体为你的机构 —— 这与网页端同一口径,Agent 绕不过。

认证、限速、错误码、计费与 REST 完全一致(§1、§7、§9)。
