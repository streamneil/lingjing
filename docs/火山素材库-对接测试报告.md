# 火山方舟 私域素材库 对接测试报告

**日期:** 2026-07-16
**目的:** 接入"私域虚拟人像素材库",让 Seedance 2.0 视频生成能使用带人脸的参考图(绕过反 Deepfake 拦截)。
**当前状态:** ❌ 卡在 **IAM 权限**,需贵方(对接方)处理后我方才能继续。

---

## 一、现象

调用 Seedance 2.0 视频生成,带人脸参考图时稳定报:

```
HTTP 400
code=InputImageSensitiveContentDetected.PrivacyInformation
message=The request failed because the input image may contain real person.
```

按火山文档《私域虚拟人像素材资产库使用指南》,解法是先把素材经 `CreateAsset` 报备入库拿到 `asset://` 再用。我方已按文档实现:AK/SK 签名调用 `open.volcengineapi.com`(ServiceName=`ark`,Version=`2024-01-01`)。

## 二、测试结果(可复现)

用贵方提供的 **Access Key** 调最基础的 `CreateAssetGroup`,返回:

```
HTTP 403  AccessDenied
User is not authorized to perform: ark:CreateAssetGroup
on resource: trn:iam::2122547722:project/*
```

**解读(关键):**

| 环节 | 结论 |
|---|---|
| AK/SK 签名 | ✅ **正确**。请求已通过鉴权、到达授权检查(否则会是 SignatureDoesNotMatch,而非 AccessDenied)。 |
| 账号 | 识别为账号 **2122547722**。 |
| IAM 权限 | ❌ **缺失**。该 Access Key 所属的 IAM 用户/角色**没有素材库操作权限**(`ark:*Asset*`)。 |
| 高级创作权益包 | ⚠️ 无法验证(被 IAM 挡在前面);见下方须确认项。 |

**即:签名和接入代码没问题,是这把 AK 的账号还没被授予素材库权限。** 权限没通,`CreateAsset` 无从谈起,所以视频生成端一直退回原图→继续被拦。

---

## 三、请对接方处理(1 项必做)

**给这把 Access Key(前缀 `AKLT…`,账号 `2122547722`)所属的 IAM 用户/用户组,附加素材库权限策略。**

火山控制台 → **访问控制(IAM)→ 权限策略 → 新建自定义策略 → JSON 编辑器**,粘贴:

```json
{
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["ark:*Asset*"],
      "Resource": ["*"]
    }
  ]
}
```

保存后 → **用户管理 → 选中该 AK 对应的用户/用户组 → 添加权限 → 选上此策略**。
(参考:火山文档《怎样管理用户对素材库的权限?》,与本策略一字不差。)

---

## 四、请对接方一并确认(2 项)

这两项现在被 IAM 挡住看不到,但会是下一道坎,请提前确认,避免来回:

1. **高级创作权益包是否已在账号 `2122547722` 开通?**
   —— 素材库 `CreateAsset` 受此权益包配额约束。请确认开通的就是这个账号(不是关联的其它账号)。

2. **调用模型的 API-KEY 与这把 AK/SK 是否同账号、同 project?**
   —— 我方生成用的模型 API-KEY(`ark-` 开头)必须与素材库 AK/SK 属于**同一账号 `2122547722`、同一 project**。素材库按 project 隔离:素材入库在 project=`default`,则模型 key 也必须在 `default`。若模型 key 在自建 project,请告知 project 名字。

---

## 五、修复后如何复验(我方执行)

贵方授权后,我方重跑一条命令即可验证,无需贵方参与:

```bash
# 1) 权限探针:应打印 group id 而非 403
npx tsx scripts/ark-asset-diagnose.ts

# 2) 带一张人脸图全链路(入库→审核→可用):
npx tsx scripts/ark-asset-diagnose.ts "<公网可访问的人脸图 URL>"
```

- 步骤 A 打印 `group id` = 权限通。
- 步骤 C 打印 `Active` = 该脸可用,生成即不再被拦。
- 若打印 `Failed` = 该图被判为**真实真人脸**(虚拟人像通道不接受,需被拍摄者本人活体认证)——这类需另议,非本次权限问题。
